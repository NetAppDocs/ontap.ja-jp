= ONTAP専用オフロードプロセッサのストレージ効率について学ぶ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
専用オフロードプロセッサによるストレージ効率化では、連続する物理ブロックを順次パッキングし、専用のオフロードプロセッサを使用して32kデータ圧縮を行います。32k圧縮では、スペース削減がボリュームレベルで実現される8kアダプティブ圧縮を使用するシステムとは異なり、スペース削減はアグリゲートレベルで実現されます。専用オフロードプロセッサによるストレージ効率化を使用するシステムは、温度依存型ストレージ効率化（TSSE）を使用しないため、圧縮はホットデータやコールドデータに基づいて行われません。これにより、パフォーマンスに影響を与えることなく、即座にスペースを削減できます。

専用オフロードプロセッサのストレージ効率化にはQuickAssist Technology（QAT）のサポートが必要であり、以下のシステムでサポートされています。記載されているAFFシステムでは、デフォルトで有効になっています。


NOTE: AFF A20システムは、専用オフロードプロセッサによるストレージ効率化をサポートしていません。AFF A20システムでは、SnapMirrorテクノロジを使用して移行されたデータは、メインCPUを使用して自動的に32kインライン圧縮に変換されます。

* AFF Aシリーズシステム：AFF A1K、AFF A90、AFF A70、AFF A50、AFF A30
* AFF C シリーズシステム：AFF C80、AFF C60、AFF C30
* FASシステム：FAS90、FAS70、FAS50


ASA r2システムおよびAFXシステムも、QATと、専用オフロードプロセッサのストレージ効率化のデフォルトでの有効化をサポートしています。

* ASA r2システムは、SANのみのお客様向けのシンプルなONTAPエクスペリエンスを備えています。link:https://docs.netapp.com/us-en/asa-r2/get-started/learn-about.html["ASA r2システムの詳細"]。
* AFXシステムは、ハイパフォーマンスNASおよびS3のお客様の固有のニーズに特化したONTAPソリューションを提供します。link:https://docs.netapp.com/us-en/ontap-afx/get-started/ontap-afx-storage.html["AFXシステムについて詳しくはこちらをご覧ください"]。


以下のシステムでは、ストレージ効率が自動的に有効になり、設定は不要です。これは、新しく作成されたすべてのシンプロビジョニングボリュームおよび既存のデータ（他のシステムから移動されたボリュームを含む）に適用されます。重複排除は、スペースギャランティの設定に関係なく有効になります。圧縮とデータコンパクションの両方において、スペースギャランティを「なし」に設定する必要があります。ボリューム移動または SnapMirror テクノロジを使用して移行されたデータは、自動的に 32k インライン圧縮に変換されます。

* AFF Aシリーズシステム：AFF A1K、AFF A90、AFF A70、AFF A50、AFF A30
* AFF C シリーズシステム：AFF C80、AFF C60、AFF C30


以下のシステムでは、ONTAP 9.15.1以降にアップグレードする前にストレージ効率が有効になっていた既存のシンプロビジョニングボリュームでのみ、ストレージ効率がデフォルトで有効になります。ONTAP CLIまたはONTAP REST APIを使用して、新しく作成したボリュームでストレージ効率を有効にすることができます。ボリューム移動またはSnapMirrorテクノロジを使用して移行されたデータは、元のプラットフォームで圧縮が有効になっていた場合にのみ、32kインライン圧縮に変換されます。

* FAS90
* FAS70
* FAS50


コントローラーをサポートされているシステムのいずれかにアップグレードする方法については、 https://docs.netapp.com/us-en/ontap-systems-upgrade/choose_controller_upgrade_procedure.html["ONTAPハードウェアアップグレードに関するドキュメント"^]を参照してください。
