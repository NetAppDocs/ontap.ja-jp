= ONTAP専用オフロードプロセッサのストレージ効率について学ぶ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
専用オフロードプロセッサによるストレージ効率化では、連続する物理ブロックを順次パッキングし、専用のオフロードプロセッサを使用して32kのデータ圧縮を行います。32k圧縮では、容量削減はアグリゲートレベルで実現されますが、8k適応型圧縮を使用するシステムでは、容量削減はボリュームレベルで実現されます。専用オフロードプロセッサのストレージ効率を使用するシステムは、温度依存型ストレージ効率（TSSE）を使用しないため、圧縮はホットデータまたはコールドデータに基づいて行われません。これにより、パフォーマンスに影響を与えることなく、即座にスペースを節約できます。

専用オフロードプロセッサによるストレージ効率化は、以下のシステムでサポートされています。リストされている AFF システムではデフォルトで有効になっています。


NOTE: AFF A20プラットフォームは、専用オフロードプロセッサのストレージ効率をサポートしていません。AFF A20システムでは、SnapMirrorテクノロジを使用して移行されたデータは、メインCPUを使用して自動的に32kインライン圧縮に変換されます。

* AFF Aシリーズシステム：AFF A90、AFF A70、AFF A50、AFF A30
* AFF A1K用
* AFF C シリーズシステム：AFF C80、AFF C60、AFF C30
* FASシステム：FAS90、FAS70、FAS50


以下のシステムでは、ストレージ効率が自動的に有効になり、設定は不要です。これは、新しく作成されたすべてのシンプロビジョニングボリュームおよび既存のデータ（他のシステムから移動されたボリュームを含む）に適用されます。重複排除は、スペースギャランティの設定に関係なく有効になります。圧縮とデータコンパクションの両方において、スペースギャランティを「なし」に設定する必要があります。ボリューム移動または SnapMirror テクノロジを使用して移行されたデータは、自動的に 32k インライン圧縮に変換されます。

* AFF Aシリーズシステム：AFF A90、AFF A70、AFF A50、AFF A30
* AFF A1K用
* AFF C シリーズシステム：AFF C80、AFF C60、AFF C30


以下のシステムでは、ストレージ効率化は、ONTAP 9.15.1以降にアップグレードする前にストレージ効率化が有効になっていた既存のシンプロビジョニングボリュームに対してのみ、デフォルトで有効になります。新しく作成されたボリュームでストレージ効率化を有効にするには、ONTAP CLIまたはONTAP REST APIを使用します。ボリューム移動またはSnapMirrorテクノロジを使用して移行されたデータは、元のプラットフォームで圧縮が有効になっていた場合にのみ、32kインライン圧縮に変換されます。

* FAS90
* FAS70
* FAS50


コントローラーをサポートされているシステムのいずれかにアップグレードする方法については、 https://docs.netapp.com/us-en/ontap-systems-upgrade/choose_controller_upgrade_procedure.html["ONTAP ハードウェア アップグレード ドキュメント"^]を参照してください。
