= ONTAP FlexVolボリュームをONTAP FlexGroupボリュームに変換する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
ONTAP 9.7以降では、データコピーや追加のディスク容量を必要とせずに、FlexVolボリュームからFlexGroupボリュームへのインプレース変換を実行できます。FlexVolボリュームをスペースの制限を超えて拡張したい場合は、ボリュームを変換できます。FlexVolボリュームをFlexGroupボリュームに変換することで、パフォーマンスが向上するだけでなく、自動的な負荷分散と拡張性も実現します。

.タスク概要
* FlexVol ボリュームを FlexGroup ボリュームに変換する処理は、業務を中断させない操作です。変換処理は通常数秒で完了し、ボリュームをオフラインにしたり、共有フォルダやエクスポートを再マウントしたりする必要がないため、クライアントは引き続きデータにアクセスできます。
* FlexVolの処理と構成が変換プロセスに対応している必要があります。
* ONTAP 9.20.1以降、ONTAP はFlexVol volumeのキャパシティを変更する際に、EMS通知およびCLIのプロンプトを通じて、FlexVol volumeをFlexGroup volumeに変換することを推奨します。変換を実行する際、元のFlexVol volumeと同じキャパシティのFlexGroup volumeを作成する必要はなく、変換時にFlexGroup volumeを拡張することができます。


.開始する前に
* 変換するFlexVolがオンラインになっている必要があります。
* FlexVolの処理と構成が変換プロセスに対応している必要があります。
+
次の条件を確認します。これらの条件に該当すると、変換が正常に行われない可能性があります。

+
** FlexGroupボリュームでまだサポートされていないボリューム上の項目は無効化または削除されています。たとえば、SAN LUN、Windows NFS、SMB1、スナップショットの命名/自動削除、vmalign設定、ONTAP 9.11.1より前のリリースでのSnapLock（SnapLockはONTAP 9.11.1以降でサポートされます）、スペースSLO、論理スペースの適用/レポートなどです。詳細については、link:supported-unsupported-config-concept.html["FlexGroupボリュームでサポートされる機能とサポートされない機能"]を参照してください。
** ONTAP 9.10.1より前のリリースでは、FlexVol volumeを所有するSVMでSVM-DRは無効になっています。ONTAP 9.10.1以降では、link:convert-flexvol-svm-dr-relationship-task.html["SVM-DRソース上のFlexVol volumeをFlexGroup volumeに変換する"]。
** FlexVolボリュームは、NetApp FlexCloneボリュームの親であってはなりません。変換対象のボリュームは、親ボリュームまたはクローンボリュームであってはなりません。
** ボリュームをNetApp FlexCacheのオリジンボリュームにすることはできません。
** ONTAP 9.7 以前では、NetAppスナップショットは 255 を超えてはなりません。ONTAP 9.8 以降では、1023 個のスナップショットがサポートされます。
** 7MTTを使用して7-Modeから移行されたFlexVol volumeは変換できません（ONTAP 9.7）。ONTAP 9.8以降では、移行されたボリュームを変換できます。
** ボリュームはアプリケーションに関連付けられていてはいけません。これはONTAP 9.7にのみ適用されます。この制限はONTAP 9.8で解除されています。
** ストレージ効率化機能は無効になっています。これらは変換後に再度有効にすることができます。
** ボリュームがSnapMirror関係のソースであり、デスティネーションがまだ変換されていない場合は、変換できません。
** ボリュームがアクティブな（静止していない）SnapMirror関係の一部である場合、その関係を静止する必要があります。
** ボリューム上で自律型ランサムウェア対策が無効になっています。変換が完了するまでは、再度有効にしないでください。
** クォータは無効になっています。変換後に再度有効にすることができます。
** ボリューム名は197文字以内です。
** ミラーリング、ジョブ、wafliron、NDMPバックアップ、処理中のinode変換などのONTAPプロセスが実行されていてはいけません。
** そのボリュームはSVMルートボリュームであってはなりません。
** ボリュームが満杯になりすぎていてはいけません。
+
これらの非互換性が存在する場合は、FlexVolに対してエラー メッセージが生成され、ボリュームの変換が中止されます。問題に対処したあと、変換を再試行できます。



* 現在のFlexVolが最大容量の80%以上に達している場合は、インプレース変換ではなく、新しく作成したFlexGroupボリュームにデータをコピーすることを検討してください。FlexGroupメンバー ボリュームは時間の経過とともに自然にリバランシングされますが、大容量のFlexVolをFlexGroupボリュームに変換すると、メンバー ボリューム間で迅速にリバランシングされないパフォーマンスやバランスの問題が発生する可能性があります。
+
[NOTE]
====
非常に大きなFlexGroupボリュームを変換すると、FlexGroupボリュームメンバーコンスティチュエントが非常にいっぱいになり、パフォーマンスの問題が発生する可能性があります。詳細については、TRlink:https://www.netapp.com/media/12385-tr4571.pdf["FlexGroupボリューム - ベストプラクティスと実装ガイド"^]の「FlexGroupボリュームを作成しない場合」というセクションを参照してください。

====


.手順
. FlexVol volumeがオンラインであることを確認します： `volume show -fields vol_name volume-style-extended,state`
+
[listing]
----
cluster-1::> volume show my_volume -fields volume-style-extended,state
vserver volume    state  volume-style-extended
------- --------- ------ ---------------------
vs0     my_volume online flexvol
----
. FlexVolを問題なく変換できるかどうかを確認します。
+
.. 上級権限モードにログインします： `set -privilege advanced`
.. 変換プロセスを確認します： `volume conversion start -vserver vs1 -volume flexvol -check-only true`
+
ボリュームを変換する前に、すべてのエラーを修正する必要があります。

+
[NOTE]
====
FlexGroupボリュームをFlexVolに戻すことはできません。

====


. 変換を開始します： `volume conversion start -vserver svm_name -volume vol_name`
+
[listing]
----
cluster-1::*> volume conversion start -vserver vs0 -volume my_volume

Warning: Converting flexible volume "my_volume" in Vserver "vs0" to a FlexGroup
         will cause the state of all Snapshot copies from the volume to be set
         to "pre-conversion". Pre-conversion Snapshot copies cannot be
         restored.
Do you want to continue? {y|n}: y
[Job 57] Job succeeded: success
----
. 変換が成功したことを確認します： `volume show vol_name -fields volume-style-extended,state`
+
[listing]
----
cluster-1::*> volume show my_volume -fields volume-style-extended,state
vserver volume    state  volume-style-extended
------- --------- ------ ---------------------
vs0     my_volume online flexgroup
----


.結果
FlexVolが単一メンバーのFlexGroupボリュームに変換されます。

.終了後の操作
必要に応じてFlexGroupボリュームを拡張できます。
