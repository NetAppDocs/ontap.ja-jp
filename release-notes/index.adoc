[[data-protection]]
== データ保護

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
xref:../data-protection/cloud-backup-with-snapmirror-task.html[SnapMirrorクラウドでの元のソースボリュームへのIn Placeリストアのサポート]
 a| 
SnapMirrorクラウドはFlexVolボリュームのIn Placeリストア処理をサポートしており、クラウドスナップショットのリストア処理を元のソースボリュームに直接実行できます。ONTAPは最新の共通スナップショットを選択して増分転送を実行し、リストア時間を短縮します。



 a| 
xref:../snapmirror-active-sync/limits-reference.html[拡張されたSnapMirrorアクティブ同期オブジェクトの制限]
 a| 
SnapMirror active syncにより、SANおよびNAS構成でHAペアごとにサポートされるボリューム数が600に増加します。



 a| 
xref:../snaplock/snapshot-lock-concept.html[SnapMirrorアクティブ同期NASでの改ざん防止スナップショットのサポート]
 a| 
ONTAPは、SnapMirrorアクティブ同期NAS FlexVolボリュームでの改ざん防止スナップショットのサポートを追加しました。この機能強化により、お客様はSnapMirrorアクティブ同期によるNASの可用性と、変更不可能なスナップショット保護を組み合わせることができます。



 a| 
xref:../data-protection/modify-svm-dr-dest-vol-capacity-task.html[強化されたSVMディザスタリカバリ]
 a| 
ONTAPは、標準の管理者権限によるボリューム変更ワークフローを使用して、SVM-DRデスティネーションボリューム上の選択されたボリューム変更属性を許可することで、SVMディザスタリカバリを強化し、サポートの支援を必要とする手順を減らします。

また、ONTAPはオプトインのSVM-DRクイック再同期サポートをFlexGroupコンスティチュエントに拡張し、大規模なFlexGroupを保持するSVMが、DRリハーサル、再同期、または反転再同期ワークフローのあとに、より迅速に保護状態に戻れるようにします。

詳細については、xref:../data-protection/resync-svm-destination-task.html[ONTAP SnapMirrorデスティネーションSVM上のデータを再同期する]を参照してください。



 a| 
xref:../data-protection/configure-backend-fc-replication.html[FC経由のSnapMirrorレプリケーションのバックエンドサポート]
 a| 
既存のファイバチャネル（FC）ファブリック経由で、バックエンドのSnapMirror非同期レプリケーションおよびSnapLock for SnapVaultを設定できます。

これにより、レプリケーショントラフィックは既存のSANインフラストラクチャ内で完全に転送されるようになります。ONTAP 9.20.1より前は、これらのレプリケーション関係のトラフィックは、クラスタ間IPネットワークのみを介して伝送されていました。



 a| 
xref:../consistency-groups/protect-task.html[非SnapLockソース整合性グループからSnapLock for SnapVault宛先整合性グループへのレプリケーション]
 a| 
非SnapLockのソース整合性グループから、SnapLock for SnapVaultのデスティネーション整合性グループにレプリケートできます。SnapLock for SnapVaultは、レプリケートされた整合性グループを誤った削除や悪意のある削除から保護します。



 a| 
xref:../san-admin/fc-sp-3-security-support.html[BroadcomセキュアHBAによるFC-SP-3認証および暗号化]
 a| 
ONTAPは、AFFおよびFASシステムのBroadcomセキュアHBAにおいて、Fibre Channel Security Protocol 3（FC-SP-3）の認証と暗号化をサポートしています。FC-SP-3のサポートにより、ハードウェアレベルのエンドツーエンドの暗号化とデバイス認証が可能になり、T11 Fibre Channelセキュリティ標準に準拠しつつ、FCおよびNVMe/FC SANホストとONTAPストレージシステム間で転送中のデータを保護できます。

暗号化処理はオフロードされるため、ストレージシステムのパフォーマンスに影響はありません。

[[fpolicy-enhancements]]
== FPolicyの機能拡張

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-nfsv4-concept.html[NFS 4.2 の FPolicy サポート]
 a| 
FPolicyはファイルアクセス監視をNFSv4.2に拡張し、最新のNFSプロトコル バージョンを使用する環境における監査、コンプライアンス、およびサイバーレジリエンスのワークフローを可能にします。FPolicyは、拡張属性書き込み（SETXATTR、REMOVEXATTR）やSETATTR/GETATTRによるセキュリティラベルの変更など、NFSv4.2ファイル操作に関する通知を生成します。NFSv4.2の通知には、protobuf形式で構成された外部エンジンが必要です。



 a| 
xref:../nas-audit/supported-file-operation-filter-fpolicy-s3.html[S3オブジェクトストレージのFpolicyサポート]
 a| 
FPolicyは、S3オブジェクトワークフローのセキュリティ監視機能を提供します。これにより、ファイルおよびオブジェクトストレージ向けの統一されたFPolicyフレームワークが提供され、ハイブリッドデータ環境におけるセキュリティ運用が簡素化されます。S3オブジェクト向けのFPolicyは、オブジェクトの作成、削除、メタデータタグの変更を監視することで、セキュリティ、コンプライアンス、監査要件を満たすためのオブジェクトライフサイクル可視化機能を提供します。この機能は、パフォーマンスに影響を与えることなく、無停止での監視を提供します。

[[nas]]
== NAS

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
xref:../smb-admin/supported-versions-functionality-concept.html[Windowsクライアント向けSMB正規化名前クエリのサポート]
 a| 
Windowsクライアントは、単一のリクエストで正規のファイル名とディレクトリ名を取得できるため、ファイルを開く際の遅延が短縮され、企業向けデスクトップ、アプリケーション、ファイルサーバーにおけるSMB互換性が向上します。ONTAPは、開いているファイルとディレクトリの正規パスを自動的に返し、追加の設定なしに、Windows 11 24H2以降のクライアントでコンポーネントごとの検索を回避します。



 a| 
xref:../nfs-admin/support-vmware-vstorage-over-nfs-concept.html[VMware NFSデータストアの自動領域解放]
 a| 
ONTAPは、NetApp NFS Plug-in for VMware VAAIを使用して、NFSデータストアの自動領域解放をサポートします。これにより、VMware ESXi 9.0以降のホストがUNMAP処理を発行した際に、シンプロビジョニングされたVMDKブロック範囲から領域を解放できます。



 a| 
xref:../volumes/cautions-increasing-maximum-directory-size-concept.html[ONTAP FlexVol ボリュームの最大ディレクトリサイズ]
 a| 
ONTAPは、最大4GBまでのディレクトリサイズに対応することで、約2500万個のファイルを含む非常に大きなディレクトリのパフォーマンスを向上させます。AIトレーニングなど、単一ディレクトリ内に非常に多くのファイルを生成するワークロードを実行しているお客様は、従来大きなディレクトリで発生していたパフォーマンス低下を回避できるため、メリットを享受できます。また、データ保護のフェイルオーバー後もディレクトリが完全にインデックス化された状態を維持することで回復力が向上し、SnapMirror関係が切断された場合でも、レプリケートされたコピーで高いパフォーマンスが発揮されます。この機能は、MetroCluster環境を含むAFFおよびFASストレージシステムで利用可能であり、必要に応じて各ボリュームで有効にすることができます。



 a| 
xref:../task_nas_provide_client_access_with_name_services.html[SIDからUNIX IDへの自動変換をサポート]
 a| 
ONTAPでは、LDAP接続されたSVM向けに、Windows SIDからPOSIX UID/GIDを生成および逆変換するための、SIDからUNIX IDへの自動変換サポートが導入されました。これにより、Active DirectoryでuidNumber/gidNumber属性を手動で管理する必要がなくなり、管理のオーバーヘッドが削減され、NFSとSMB全体で一貫したファイルアクセスを確保できるようになります。この業界標準に準拠した機能は、SSSDベースのNASプラットフォームから大規模ネットワークを移行し、IDマッピングの一貫性を維持したいお客様にとって特に価値があります。この機能はデフォルトでは無効になっており、SVMごとに設定します。

[[san]]
== SAN

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
xref:../revert/remove-persistent-reservation-registrations.html[SCSI永続的予約登録スケールの増加]
 a| 
LUNあたりのSCSI-3永続的予約の登録数の最大サポート数が182から256に増加します。これにより、VMwareゲストクラスタリングやWindows Serverフェールオーバークラスタリングなどの大規模なクラスタSAN環境において、永続的予約の管理ワークフローを変更することなく、共有LUN上でより多くのホスト登録をサポートできるようになります。

 a|

 a| 
xref:../svm-migrate/migrate-svm-task.html[ASA r2システムからASAまたはAFFシステムへのストレージVMの無停止移行のサポート]
 a| 
ストレージ仮想マシン（SVM）を、2ノードのASA r2クラスタから2ノードのASAまたは2ノードのAFFクラスタに無停止で移行できます。移行中も、LUNおよびネームスペースの既存のホストマッピングとストレージユニット構成は維持されるため、運用上の労力とリスクが軽減されます。

[[s3-object-storage]]
== S3オブジェクト ストレージ

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
xref:../s3-snapmirror/index.html#snapmirror-s3-requirements[MetroClusterでのSnapMirror S3のサポート]
 a| 
スイッチオーバーおよびスイッチバックの実行後も引き続き利用可能で、アクティブサイトから再開できるSnapMirror S3関係を、MetroCluster構成で作成できます。



 a| 
xref:../s3-config/create-bucket-lifecycle-rule-task.html[MetroClusterによるONTAP S3バケットのライフサイクル管理のサポート]
 a| 
MetroCluster構成のネイティブS3バケットに対して、ONTAP S3バケットのライフサイクル管理ルールを作成できます。



 a| 
xref:../s3-config/create-s3-object-store-server-task.html[柔軟なS3バケットサイズ設定]
 a| 
ONTAPは、新しいS3バケットに対して設定可能なデフォルトサイズをサポートしています。これは、アプリケーションが容量を指定せずにS3 API経由でバケットを作成する際に、手動でのサイズ変更を減らすのに役立ちます。デフォルトサイズが設定されていない場合、バケット作成の動作は変更されません。



 a| 
xref:../s3-multiprotocol/create-nas-bucket-task.html[S3 NASバケット（FlexCacheボリューム上、FlexVolオリジン）]
 a| 
S3 NASバケットは、FlexCacheボリューム（FlexVolオリジン）でサポートされています。単一オブジェクトに対するS3操作（PUT、GET、DELETE、HEAD、LIST）がサポートされています。基盤となるFlexVolボリュームがGranular Data Distributionをサポートしていないため、マルチパートアップロードはサポートされていません。



 a| 
xref:../s3-multiprotocol/create-nas-bucket-task.html[FlexCacheボリューム上のNASバケットに対するS3サーバー側コピーのサポート]
 a| 
FlexCacheボリューム上のS3 NASバケットは、S3のCopyObjectおよびUploadPartCopy APIを使用したサーバー側のオブジェクト コピー処理をサポートします。同じFlexCache NASバケット内でオブジェクトをコピーしたり、FlexGroupボリュームをバックエンドとするS3 NASバケットからFlexCache NASバケットにオブジェクトをコピーしたりできます。



 a| 
xref:../s3-config/ontap-s3-supported-actions-reference.html[ONTAP S3フレキシブルチェックサムサポート]
 a| 
ONTAP S3は、S3 NASバケット向けにAWS互換のCRC-64NVMEチェックサムをサポートしています。S3クライアントが、サポートされているアップロードおよびマルチパート操作のチェックサム情報を提供すると、ONTAPはチェックサムを検証して保存し、サポートされているGETおよびHEADリクエストに対してチェックサム情報を返します。

[[security]]
== セキュリティ

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
Apacheの管理接続フラッドに対する公平なキューイングとプレクラスタ機能の強化
 a| 
ONTAPは、管理Webサーバーにオプトイン（デフォルトはオフ）の送信元IPベースの均等化キューイングを導入し、管理接続のフラッド時にもREST、System Manager、およびONTAPIへのアクセスを維持できるようにします。ONTAPはまた、プレクラスタ専用のREST APIを介したイメージのインストールをサポートし、動的ホスト構成プロトコル（DHCP）の処理を強化することで、ノードがクラスタのセットアップを待機している間、リースの更新やIPアドレスの変更があってもプレクラスタのノード管理LIFを引き続き利用できるようにします。



 a| 
xref:../anti-ransomware/modify-snapshot-options-arpai.html[ARP/AIスナップショット応答ポリシーの制御機能の強化]
 a| 
ARP/AIが異常なアクティビティを検出した際にスナップショットを作成するかどうかを制御するために、SVMまたはボリュームレベルでARP/AIスナップショット応答ポリシーを設定できます。利用可能なポリシーは3つあります： `alert-with-proactive-and-periodic-snapshot`（デフォルト、既存の動作を維持）、 `alert-with-proactive-snapshot`（攻撃時のスナップショットのみ、定期的なスナップショットはなし）、および `alert-only`（アラートとイベントログのみ、スナップショットは作成されません）。9.20.1へのアップグレード後、ノードレベルのオプションが以前に変更されていない限り、デフォルトの定期スナップショットの最大カウントは6から2に変更され、デフォルトの保持期間は12時間から7時間に変更されます。



 a| 
xref:../encryption-at-rest/enable-external-key-management-96-later-nve-task.html[データSVMのキー管理ワークフローの改善]
 a| 
データSVMで外部キーマネージャを有効にすると、ONTAPは、そのSVMのボリューム暗号化キーを管理者スコープのキーマネージャから新しいデータSVMキーマネージャに自動的に移行できます。これにより、外部キー管理への移行が簡素化され、標準ワークフローにおける別途の手動移行手順が不要になります。



 a| 
xref:../multi-admin-verify/index.html[MAV承認者としてのIdP、AD、LDAPグループのサポート]
 a| 
MAV承認グループには、個々の管理者に加えて、IDプロバイダー（IdP）、Active Directory（AD）、およびLDAP（nsswitch）グループを承認者として含めることができます。サポートされるグループの種類には、Entra ID、ADFS、ADドメイングループ、およびLDAPグループが含まれます。IdP、AD、またはLDAPディレクトリでのユーザーの追加や削除で、MAV構成を変更する必要はありません。ユーザーのグループメンバーシップの変更は、ユーザーが次回ログインした際の再認証後に有効になります。security multi-admin-verify registered-operations showコマンドを使用すると、現在のクラスタで使用可能なMAV保護対象のすべての操作を表示できます。



 a| 
xref:../networking/configure_snmpv3_users_in_a_cluster.html[SNMPv3 SHA-512認証のサポート]
 a| 
ONTAPは、SNMPv3ユーザー向けにSHA-512認証をサポートしています。この機能強化により、外部SNMPクライアントおよびスイッチ監視（SHA-512認証を必要とするスイッチを含む）において、より強力なSNMPv3認証を使用できるようになります。詳細については、ONTAPクラスタでのSNMPv3ユーザーの設定、およびイーサネットスイッチの健常性監視のためのSNMPv3の設定を参照してください。

詳細については、 https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["イーサネットスイッチの状態監視のためにSNMPv3を設定する"]を参照してください。

[[storage-efficiency-enhancements]]
== Storage Efficiencyの機能拡張

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
xref:../concepts/capacity-measurements.html[ストレージ効率のデータ削減率レポートの簡素化]
 a| 
ストレージ効率のデータ削減率（DRR）は、削減可能なデータのみを含めることで、ONTAPのストレージ効率によるスペース削減量をより正確に評価します。ONTAP 9.19.1以前では、DRRには削減可能なデータと削減不可能なデータの両方が含まれます。



 a| 
xref:../concepts/builtin-storage-efficiency-concept.html[非QATシステムからQATシステムへのボリューム移行後のパフォーマンス向上]
 a| 
ONTAPは、QuickAssist Technology（QAT）をサポートしていないシステムからサポートしているシステムへボリュームを移行したあとに発生する可能性のある、追加の読み取りレイテンシとCPU使用量を削減します。



 a| 
自動重複排除スケジューラ（ADS）の最適化
 a| 
ONTAPはADS（自動重複排除スケジューラ）のパフォーマンスを向上させ、ノードあたりの同時重複排除セッション数を増やすとともに、よりスマートで的を絞ったスロットリングによってクライアントI/Oのバランスを最適化します。DPボリュームでの重複排除アクティビティ（SnapMirror転送によるもの）とグローバル重複排除セッションは、通常のボリューム重複排除と並行して管理されるため、競合とメタデータの増加が抑制されます。特に混合ワークロード環境において、構成変更なしでストレージ効率の向上によるコスト削減効果を享受できます。この機能はデフォルトで有効になっており、AFFストレージシステムで利用できます。

[[storage-resource-management-enhancements]]
== ストレージ リソース管理の機能拡張

[cols="30%,70%"]
|===
| 更新 | 概要 


 a| 
xref:../s3-config/delete-recover-bucket-with-data-task.html[オブジェクトを含むONTAP S3バケットの削除のサポート]
 a| 
管理者は、設定可能な保持期間ベースの復旧期間を使用する場合、オブジェクトを含むバケットの削除をスケジュールできます。これにより、保持期間が終了する前にバケットを復元することが可能になります。この機能により、有効期限切れのバックログが削減され、変更の激しいワークロードにおける容量の再利用が迅速化されます。



 a| 
xref:../flexcache/sizing-concept.html[FlexCacheサイジング制限の増加]
 a| 
ボリュームごとに1つの構成要素を使用する場合、サポートされるFlexCacheボリュームの数はノードあたり2500、HAペアあたり5000に増加します。

オリジンボリュームから作成できるFlexCacheボリュームの数が200に増加し、オリジンあたりのライトバックキャッシュの数が50に増加します。



 a| 
xref:../flexcache/supported-unsupported-features-concept.html[FlexCacheでのNVFailのサポート]
 a| 
NVFAILが有効なオリジンとのFlexCache関係を作成できます。キャッシュボリュームに対しても、オリジンボリュームとは独立してNVFAILを有効にできます。NVFAILが発生したオリジンボリュームまたはキャッシュボリュームでは、ONTAPはデータの読み取りや変更をブロックしつつ、変更されたキャッシュデータの書き戻しは維持し、復旧後に通常のI/Oが再開されます。



 a| 
非同期削除のパフォーマンス向上
 a| 
ONTAPは、非同期削除のパフォーマンスを向上させ、NAS/SMBクライアントの領域解放を加速します。詳細については、NetAppの担当者にお問い合わせください。



 a| 
xref:../data-protection/calculate-reclaimable-space-task.html[FlexGroupボリュームでの再利用可能なスペースの計算のサポート]
 a| 
ONTAPは、FlexGroupボリューム上のスナップショットを削除する前に、再利用可能な領域を再計算することをサポートしています。



 a| 
xref:../flexgroup/provision-automatically-task.html[ハイパフォーマンスなFlexGroupボリュームの自動プロビジョニング]
 a| 
ONTAPは、お客様がワークロードに合わせてバランスの取れた、またはハイパフォーマンスなデータ コンテナを選択できるストレージプロファイルを使用して、FlexGroupのプロビジョニングを簡素化します。これにより、管理者がパフォーマンス要件を満たすために構成ボリュームを手動で設定およびサイジングする必要性が軽減されます。



 a| 
xref:../flexgroup/enable-adv-capacity-flexgroup-task.html[高度な容量再配分機能を備えたSMBマルチチャネルサポート]
 a| 
ONTAPは、FlexGroupボリュームで高度な容量バランスが有効になっている場合、SMBマルチチャネルの使用をサポートします。



 a| 
xref:../svm-migrate/index.html#supported-and-unsupported-features[S3 NASバケットのSVM移行サポート]
 a| 
ONTAPは、FlexVolボリューム上でS3 NASバケットをホストするSVMのSVM移行をサポートしており、管理者はS3 NAS構成を事前に削除することなくSVMを移行できます。



 a| 
xref:../task_nas_file_system_analytics_view.html[ファイルシステム分析におけるアクセス時間の保持]
 a| 
File System AnalyticsのスキャンとSystem Manager File System Explorerのブラウジングでは、ディレクトリのアクセス時間（atime）メタデータが保持されます。これにより、アーカイブ、階層化、コンプライアンス、およびデータのライフサイクルワークフローの正確なatime値を維持できます。



 a| 
xref:../volumes/manage-svm-capacity.html[ONTAP SVMの容量制限に対するMetroCluster IPのサポート]
 a| 
MetroCluster IP構成の一部であるSVMのストレージ制限を設定できます。



 a| 
FlexCacheボリューム指標
 a| 
FlexCacheボリュームのメトリクスは、FlexCacheボリュームとそのオリジンボリューム間で交換されたデータおよびメタデータの量を報告します。既存のONTAP RESTボリュームの統計およびメトリクスエンドポイントに2つの新しいプロパティが追加され、FlexCacheからオリジンへ、およびオリジンからFlexCacheへのデータ転送を可視化できるようになりました。カウンタは設定不要で自動的に収集され、キャパシティプランニング、パフォーマンス分析、ネットワークのトラブルシューティング、およびチャージバック分析に役立ちます。この機能を使用するには、FlexCacheノードとオリジンノードの両方でONTAP 9.20以降が必要です。詳細については、link:https://docs.netapp.com/us-en/ontap-automation["ONTAPの自動化"^]のドキュメントを参照してください。



 a| 
クラスター内リバランス
 a| 
ONTAPでは、ワークロードやクラスタ容量の変化に合わせて、最小限の管理作業でクラスタのパフォーマンスを最適に維持できるよう、2つの新しいバランス配置機能が導入されました。プロビジョニング時の配置制御により、お客様はREST APIを介して新しいボリュームを配置する際に、パフォーマンス要件とスペース要件のどちらを優先するかを指定できます。Space Performance Rebalance（SPR）は、クラスタ全体で発生しつつあるパフォーマンスのホットスポットや、アグリゲートのスペースの逼迫を継続的に監視するバックグラウンドプロセスです。設定されたモードに応じて、SPRはEMS通知を介して修正のためのボリューム移動を推奨するか、標準的で無停止のONTAPボリューム移動処理を使用して移動を自動的に実行します。詳細については、link:https://docs.netapp.com/us-en/ontap-automation["ONTAPの自動化"^]のドキュメントを参照してください。
