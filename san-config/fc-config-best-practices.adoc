= ONTAPシステムでFCファブリックを構成するためのベストプラクティスについて学習します
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
FCファブリック構成のベストプラクティスに従うことで、ファブリック変更時のホストおよびターゲットのパフォーマンス、信頼性、安定性が向上します。

.推奨されるFCファブリック構成のベストプラクティス
* *シングルイニシエータ / シングルターゲット（SI/ST）ゾーニング*
+
SI/STゾーニングは、ファブリック変更時のレイテンシースパイクを低減し、クロストークを排除し、登録状態変更通知（RSCN）を制限し、トラブルシューティングを簡素化し、パス数をホストの制限内に抑えます。

+
** ホストへの影響：SI/STゾーニングにより、予測可能なMPIO動作、より高速な検出、および全パスダウン（APD）/永久デバイス損失（PDL）イベントの減少が保証されます。
** 目標とする効果：SI/STゾーニングにより、ログイン/ログアウトイベントが減少し、FCセッションが安定します。


* *ターゲットLIF WWPN（物理ポートではない）を使用したWWPNベースのゾーニング*
+
WWPNベースのゾーニングにより、LIFの移動、テイクオーバー/ギブバック、再ゾーニングなしでの無停止運用が可能になり、メンテナンス中のパスのリセットを防ぐことができます。

+
** ホストへの影響：WWPNベースのゾーニングにより、LIFの移動時やコントローラのフェイルオーバー時にもパスの損失が発生しないことが保証されます。
** ターゲットへの影響：WWPNに基づくゾーニングにより、ONTAPはターゲットLIFを透過的に移動できます。


* *すべてのFCスイッチでNPIVが有効になっています*
+
ファブリックに接続されているすべてのスイッチは、NPIVをサポートし、NPIVが有効になっている必要があります。ONTAPは、N_Port ID仮想化（NPIV）を使用してFCターゲットを提示します。これがないと、ターゲットLIFは正しくログインできません。

+
** ホストへの影響：NPIVは、断続的なパスの切断やデバイスの欠落を防ぎます。
** ターゲットへの影響：NPIVは、ターゲットLIFの可視性と安定したFCログインを保証します。


* *完全に分離された2つの独立したファブリック*
+
デュアル独立ファブリックは、2つの独立した物理スイッチ、電源、およびケーブルで構成されます。ファブリックAとファブリックBは決して互いに接続されません。それぞれが独自のFCネームサーバー、ゾーンセット、ドメインIDを保持しています。ファブリックが完全に分離されているため、単一障害点が存在しません。一方のファブリックが稼働を継続している間でも、もう一方のファブリックに対して無停止メンテナンスを実施できます。

+
** ホストへの影響：独立した2つのファブリックにより、ファブリックのファームウェアのアップグレードや障害発生時にも継続的なI/Oがサポートされます。
** ターゲットへの影響：独立した2つのファブリックにより、スイッチの問題発生時にも冗長なターゲットアクセスが維持されます。


* *FCポート速度の固定（自動ネゴシエーションの回避）*
+
自動ネゴシエーションは、ファブリックの再構築を遅らせたり、速度の不一致を引き起こしたり、再収束の遅延やリンクフラップにつながる可能性があります。

+
** ホストへの影響：FCポートの速度が固定されているため、リンクリセット時の停止時間が短縮されます。
** 目標とする効果：FCポートの速度を固定することで、ノードまたはスイッチのイベント発生後にポートがより速く起動するようになります。


* *NetApp相互運用性マトリックスツール（IMT）で検証済みの構成（HBA、ドライバ、ファームウェア、スイッチ）の厳守*
+
 https://mysupport.netapp.com/matrix["NetApp IMT"^]で検証された構成に厳密に従うことで、期待されるレイテンシとスループットが維持されます。

+
** ホストへの影響：IMT検証済みの構成を使用することで、原因不明のI/Oエラーやタイムアウトを回避できます。
** 目標とする効果：IMT検証済みの構成を使用することで、プロトコルレベルの非互換性を防止できます。


* *FCエラーカウンタ（CRC、同期損失、RECV_ERROR）のプロアクティブな監視*
+
ファブリックエラーは、ONTAPストレージカウンタが検出する前に、ホスト側のレイテンシやI/Oエラーとして現れることがよくあります。FCエラー数をプロアクティブに監視することで、持続的なレイテンシの増加を防ぐことができます。

+
** ホストへの影響：プロアクティブな監視により、早期発見が可能になり、ホストのI/O再試行やアプリケーションの停止を防ぎます。
** 目標とする効果：プロアクティブな監視により、ファブリックの問題をストレージの問題と誤認することを防ぎます。


* *SANトラフィックのスイッチ間リンク（ISL）のオーバーサブスクリプションを回避してください*
+
ISLの輻輳は、クレジットの枯渇とスロードレイン動作を引き起こします。

+
** ホストへの影響：ISLのオーバーサブスクリプションを回避することで、ホストI/Oの待ち時間とキューイングを削減します。
** ターゲットへの影響：ISLのオーバーサブスクリプションを回避することで、ONTAP FCポートへのバックプレッシャを防ぎます。
