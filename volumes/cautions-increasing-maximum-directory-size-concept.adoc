= ONTAP FlexVol ボリュームの最大ディレクトリサイズ
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
FlexVol volume上のディレクトリの最大サイズを設定できます。設定すべき最大サイズは、ONTAPのリリースとお客様固有の構成によって異なります。ONTAPのディレクトリサイズ制限機能はONTAP 9.20.1で強化され、より大きなディレクトリサイズをサポートするようになりました。


NOTE: 最大ディレクトリサイズの設定は、個々のFlexVolボリュームだけでなく、FlexGroup内のすべてのボリュームにも適用されます。



[[considerations-for-directory-size-limit-processing]]
== ディレクトリサイズ制限処理に関する考慮事項

ディレクトリのサイズは、含まれるファイル、フォルダ、その他のエントリの数、および名前の長さによって異なります。この合計サイズが増加すると、パフォーマンスや、ONTAPがディレクトリを効率的に管理する機能に影響を及ぼす可能性があります。 `maxdir-size`コマンドパラメータを使用して、ディレクトリの最大サイズを制限できます。ディレクトリの最大サイズは、特定のボリュームに対して一度設定され、そのボリューム上のすべてのフォルダに適用されます。



[[operational-characteristics]]
=== 運用特性

最大サイズの設定と適用に関連するONTAPのディレクトリ処理には、いくつかの特徴があります。

デフォルトの最大値:: ONTAP 9.20.1より前のリリースにおけるデフォルトの最大ディレクトリサイズは320 MBです。正確な値はモデルによって異なり、プラットフォームのシステムメモリ容量に合わせて最適化されます。モデル固有の詳細とデフォルトについては、 https://hwu.netapp.com/["NetApp Hardware Universe"^]を参照してください。
ディレクトリの最大サイズを増やす:: デフォルトの最大値は、一般的なビジネスアプリケーションをサポートするほとんどのワークロードに適しています。ほとんどの環境では、この値を変更する必要はありません。必要に応じて、CLIコマンド `volume create`および `volume modify`の `-maxdir-size`パラメータを使用して、許可される最大ディレクトリサイズを増やすことができます。
推奨上限:: NetAppは一般的に、一部のディレクトリがこのサイズを安全に超えることが確認されている場合でも、ディレクトリを1GBを超えて拡張することは推奨していません。ONTAP 9.20.1より前のバージョンでは、サイズが大きすぎるとパフォーマンス上のリスクがあります。




[[performance-considerations]]
=== パフォーマンスに関する考慮事項

ディレクトリのサイズは、特に非常に大きくアクティブなディレクトリの場合、検索パフォーマンスに直接影響します。ディレクトリが大きくなるにつれて、ONTAPは名前検索を高速化するために内部インデックスを自動的に構築するため、ほとんどのリクエストではディレクトリ全体をスキャンする必要がありません。

しかし、持続的な高速ファイルの作成と削除が行われると、インデックス管理プロセスが受信する変更の速度に追いつかなくなる可能性があります。場合によっては、これにより部分的にしかインデックス化されていない大きなディレクトリが作成されることがあります。この場合、検索およびディレクトリ一覧表示のリクエストにおいて、パフォーマンスが著しく低下する可能性があり、インデックス作成処理が追いつくまでその状態が続きます。



[[enhanced-directory-size-supporting-25-million-files]]
== 25 millionファイルをサポートする拡張ディレクトリサイズ

ONTAP 9.20.1以降では、以前のONTAPリリースの制限を超えて、最大ディレクトリサイズ値を安全に増やすことができます。9.20.1以降での上限は4 GBです。これにより、約2500万個のファイル、フォルダ、その他のエントリをサポートできます。この機能強化は、AIなど、単一のディレクトリ内に非常に多くのファイルを必要とするワークロードをサポートするように設計されています。



[[two-step-configuration-process]]
=== 2段階の設定プロセス

より大きなディレクトリを安全にサポートできるようにボリュームを設定するには、2つのステップが必要です。ボリュームを作成する際、または既存のボリュームを変更することで、構成を実行できます。手順は以下のとおりです：

* この機能を有効にします。特定のボリュームに対して、 `volume create` または  `volume modify` コマンドを使用して、パラメータ  `-is-dir-index-transfer-enabled` をデフォルトの  `false` から  `true` に設定する必要があります。
* ディレクトリの最大サイズを増やします。ボリュームの最大値は、ボリュームの作成時またはその後の変更時に `-maxdir-size`パラメータを使用して設定できます。これは、9.20.1より前のONTAPシステムで使用されていたものと同じパラメータです。


これら2つの設定は独立しているため、設定を行う順序は自由です。ただし、ボリュームディレクトリが設定された最大サイズまで拡張される前に、まず拡張サイズオプションを有効にすることをNetAppではお勧めします(`-is-dir-index-transfer-enabled`）。この機能が有効になる前にディレクトリのサイズが大きくなった場合、そのオプションが有効になり、関連するバックグラウンド変換プロセスが完了するまで、改善によるメリットを十分に享受することはできません。



[[benefits]]
=== メリット

ディレクトリの最大サイズが拡張されたことで、いくつかの改善点がもたらされます：

* 強化されたディレクトリインデックス機能は、高速かつ大量のファイル作成および削除要求に対応し、インデックス化されていない大規模なディレクトリが発生するリスクを低減します。
* ディレクトリインデックス情報はSnapMirrorデスティネーションボリュームにレプリケートされます。SnapMirror関係が解除された場合でも、デスティネーションボリュームのインデックスは保持され、高いパフォーマンスを維持します。
* バックグラウンドでの整合性チェック中のディレクトリアクセスが高速化されるため、大規模なディレクトリがシステム健全性チェックに与える影響が軽減されます。
* 検索パフォーマンスはより幅広い操作において一貫性が高く、ディレクトリのインデックスが利用できない場合でも信頼性の高い代替手段を提供します。




[[enhanced-internal-processing]]
=== 内部処理の強化

拡張ディレクトリ最大サイズオプションを有効にすると、ONTAPは、ボリュームの既存のディレクトリインデックス情報を新しい柔軟なフォーマットに変換するバックグラウンドスキャナを起動します。この処理は非同期で実行され、特に既存のディレクトリが多数存在するボリュームの場合、完了までに時間がかかります。既存の大規模なディレクトリでは、スキャン処理が完了するまで、パフォーマンスとレプリケーションのメリットを十分に享受できない可能性があります。

ボリュームでこのオプションを有効にしたあとは、無効にしようとしないでください。無効にするとバックグラウンド スキャナが起動し、ディレクトリ インデックス情報が元の形式に変換されます。オプションが完全に元に戻るには、スキャナの処理が完了する必要があります。



[[restrictions-and-cautions]]
=== 制限事項と注意事項

 `-is-dir-index-transfer-enabled`パラメータを使用して機能を有効にする前に、以下の制限事項にご注意ください：

* S3デュアリティとは互換性がありません。S3デュアリティでサポートできるディレクトリ内のオブジェクト数には、既知の制限があります。これら2つの機能は排他的であり、同時に使用しないでください。
* SnapMirror同期またはSnapMirror active sync NAS関係にあるボリューム、またはこれからその関係に配置する予定のボリュームではサポートされていません。
* SVM移行の候補となるボリュームではサポートされていません。
* SnapMirror非同期およびSnapMirrorクラウドのデスティネーションは、ONTAP 9.17.1以降を実行している必要があります。それ以前のリリースへのレプリケーションはサポートされていません。
* この機能が有効になっているボリュームでは、論理ディレクトリレプリケーション（LDR）はサポートされていません。
* SnapMirrorデスティネーション（DP）ボリュームで直接有効にすることはできません。その状態は常にソースボリュームに追従します。
* FlexCacheボリュームは、元のボリュームからのディレクトリインデックス情報をキャッシュしません。この機能の有効化状態は、元のボリュームからキャッシュに同期されますが、基となるインデックス変換は元のボリュームにのみ適用されます。


ボリュームでこの機能を有効にする前に、データ保護トポロジを必ず確認してください。これらの制限は、SnapMirror関係やSVM移行など、既存または将来の計画に影響を及ぼす可能性があります。
